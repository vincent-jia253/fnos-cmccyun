# 移动云盘（cmccyun）飞牛 fnOS 挂载应用

把**中国移动云盘 / 139 云盘**（`yun.139.com` 个人云）挂载成飞牛 fnOS 上的一个本地文件夹，
在「文件」应用里像本地磁盘一样浏览、下载、上传、改名、删除；附带一个网页管理台用于填授权、
换挂载点、切只读、看日志。

- 应用名：`cmccyun`（显示名「移动云盘」）
- 版本：**1.3.2**，平台 `all`（内置 linux/amd64 与 linux/arm64 两个二进制，CGO_ENABLED=0，无外部依赖）
- 安装包：`./build.sh` 产出的 `cmccyun.fpk`（发布版见仓库 Releases，md5 记在对应的 Release 说明里）
- 管理台端口：**19898**（`http://<NAS_IP>:19898/`）

---

## 1. 原理与边界（先看这段）

| 方案 | 能否整盘挂载 | 说明 |
|---|---|---|
| 官方开放平台 `open.yun.139.com` | ❌ | 定位是「把云盘能力嵌进第三方 App」，创建/上传被限制在「我的应用收藏 / appName」目录下，无法挂载任意目录 |
| 网页版私有接口 | ✅ | `yun.139.com` + 动态个人云主机，请求头 `Authorization: Basic base64("pc:账号:token")` + `Mcloud-Sign`。Alist / OpenList 的 `139`(`personal_new`) 驱动走的就是这条路 |

本应用用的是**第二方案**：逆向的网页私有接口 + 纯 Go 的 FUSE 文件系统。
因此有两点必须知道：

1. **非官方接口**：云端改版就可能失效，届时需要重新抓包适配（代码集中在 `cmccyun-src/internal/api/`）。
2. **授权会过期**：管理台保存的 `Authorization` 类似网页登录态，一般 **30 天**左右失效；
   失效后文件系统报错、管理台提示鉴权失败，重新抓一个新的 `Authorization` 粘进去即可。
   （守护进程会**每 6 小时检查**、剩余不足 15 天时自动用 AAS 接口续期并把新授权写回 `config.json`；
   并且从 v1.1.1 起，**任何接口只要被服务端以鉴权原因拒绝，就立刻强制续期并自动重试一次**，
   所以即使后台续期没赶上，正在进行的操作也不会立刻失败。整条链路都不需要手工换授权，
   只有续期本身也失败（例如令牌已彻底作废）时才要重新抓一条粘进来。）

   > **控制台里那个「授权 剩余 N 天」是什么**：它是这条 `Authorization` **本身**的剩余有效期，
   > 由云盘服务端写死在令牌里（令牌形如 `pc:账号:<令牌>|<b>|RCS|<到期毫秒时间戳>|密钥`，程序读第 4 段），
   > **不是会员到期日、也不是本地估算**。所以它是个实时倒计时（保留 1 位小数，例如「29.7 天」），
   > 每天自然递减，不用管它；剩余不足 15 天时后台会自动续期，续期成功后回到约 30 天
   > （「授权」页会显示「上次自动续期 …」）。徽标在 >15 天时是正常色、<15 天变黄提示。
   > **实测（2026-10-12 真实账号）**：手动点「刷新令牌」→ 新到期 2026-11-11 00:40（整整 30.0 天），
   > 新令牌已写回 `config.json`，随后用新凭据列云端目录 / 真读文件都正常 —— 续期确实有效，30 天到期不会断。

### v1.3.0 变更：修掉「挂载永远停在正在挂载」的死锁 + 状态显示 + 界面重做

用户反馈两件事：**① 点挂载后一直显示「正在挂载」，永远不结束；② 管理台太丑。**
第一件事查出来是**真 bug，而且很严重**：不是慢，是**自己把自己锁死了**。

| 变更 | 说明 |
|---|---|
| **死锁根因** | `Service.Update()`（处理「保存设置」）在**已经持有 `s.mu`** 的情况下调用了 `s.validateMountPath(v)`，而后者内部又去 `s.mu.Lock()`（经 `curMountPoint()`）—— Go 的 `sync.Mutex` 不可重入，于是这个 goroutine 永久阻塞，**后续所有控制台接口（状态/配置/挂载/卸载）全部排在它后面卡住**。用 `kill -QUIT` 打 goroutine 栈确认：60 多个 goroutine 卡在 `sync.Mutex.Lock`。表现就是「正在挂载」转圈不停，`/api/status` 也超时；界面本身是静态的所以还能打开，进一步误导成「后端很慢」 |
| **锁纪律（写进代码注释）** | `Service` 的方法命名约定：**带 `Locked` 后缀 = 调用方必须已持锁；不带后缀 = 自己加锁**，两者不得混用。`validateMountPath{,Opt}`（自锁）与 `validateMountPath{,Opt}Locked`（需持锁）拆成两套；`strayMount` → `strayMountLocked`；`Status()` 在锁内取状态、**放锁后**才做文件系统探测（绝不在持锁时做 IO） |
| **死锁看门狗回归测试** | 新增 `internal/app/deadlock_test.go`：5 秒超时逐个调用所有控制台入口（`Update(mount_point)`、`CheckMountPath`、`Status`…），超时即失败并打印全部 goroutine 栈。**改回旧写法该测试立刻失败**（已验证），所以这个坑不会再回来 |
| **挂载状态显示（已挂载 / 未挂载）** | 顶部状态卡直接写明白：大字「已挂载 / 未挂载」+ 挂载路径（带一键复制）、账号、模式（只读/读写）、属主 uid:gid、令牌剩余天数、是否开机自动挂载、进程 PID；**每 5 秒自动刷新**，无需手动点。挂载/卸载/重挂载按钮会显示加载态并禁用，请求有超时保护（不再"转圈到天荒地老"），成功/失败都有气泡提示 |
| **残留（僵尸）挂载自动清理** | 上次进程被 `kill -9` 或掉电后，`/proc/mounts` 里会留下一个"空壳"挂载点，一访问就 `ENOTCONN`（"Transport endpoint is not connected"），以前会被当成"已挂载"从而拒绝再挂。新增 `vfs.Dead(dir)` 识别这种挂载：启动时、点挂载时都会**先卸掉再重挂**；配置路径与残留路径不一致时界面给出提示并提供**一键清理**按钮 |
| **界面重做** | 按页签分区：**挂载设置 / 授权 / 云盘浏览 / 运行日志**；统一的深色/浅色主题、状态卡、气泡提示（toast）、按钮加载态、表单分组；手机窄屏与深色模式一并适配；目录选择器保留（v1.2.1 的「文件夹树 + 内容」两栏） |

截图见 `docs/screenshots/console-v1.3.0-*.png`（截图不入库，仅本地留存）。

### v1.2.1 变更：位置选择器改成「文件夹树 + 目录内容」（并顺手修掉一个能遮住文件的坑）

v1.2.0 的选择器是**一长条平铺列表**（把各卷下的候选目录全列出来），用户直接否掉：
「我要的是像进文件夹那样，或者有个文件树可以选，而不是都列出来」。v1.2.1 把它重做成文件管理器式两栏。

| 变更 | 说明 |
|---|---|
| **两栏目录树** | 左边是可展开/收起的文件夹树（`▸/▾` 展开、点名字选中），右边是所选目录里的内容（点一行就进去，带「⬆ 上一级」）；两侧都有固定表头（树 / 路径 + `↻ 刷新`）。默认隐藏 `@appcenter` 等系统目录，可勾「显示系统目录」。另有「路径」输入框可直接跳转（回车或点「跳转」），「在选中目录里新建文件夹」建在**当前选中**目录里 |
| **只列真正的存储卷** | 飞牛会在根目录预建 `/vol00`、`/vol01`、`/vol02` 这类**占位目录**（它们其实是系统盘上的普通目录，里面甚至有空壳的个人空间目录）。以前它们会被当成可选的卷列进树里，挂进去既不在「文件」里显示、又会把系统盘塞满 —— 现在只认**真正挂上了文件系统的卷**（`/vol1`…`/vol4`） |
| **快捷入口只给真实存在的用户** | 快捷入口里以前会出现 `/vol1/1001` 这种**已删用户残留目录**（uid 1010+ 查不到用户名），点进去只有孤儿文件。现在只列能解析出用户名的个人空间，并把**当前挂载点所在的卷排最前**（`个人空间（用户名）· /vol4` / `当前挂载点`） |
| **能从「个人空间根」里挪出来** | 真机上踩到：把云盘挂在 `/vol4/1000`（个人空间的**根**）会遮住用户原有的文件夹（`302`、`临时`、`游戏`…）。想再挪进 `/vol4/1000/移动云盘` 时，这个路径的「真身」正被挂载遮着 —— 以前会被规则直接拒掉，现在**先卸下当前挂载点、再核对/创建真实目录、最后挂上**，并在选择器里明确提示。反过来，绝不允许把目录**建到**当前挂载点里面（那会写进云盘里），会给出对应提示 |
| **选中当前挂载点时不再误报** | 挂在某个目录上时去检查它自己，后端以前会把「透过挂载看到的条目数」报成 0，前端就误判成「空」或「非空」。现在挂着的时候也会给出真实条目数，前端显示「这就是当前的挂载点（N 项，都是云盘里的内容）」 |

### v1.2.0 变更：挂载位置任选（能挂进「我的文件」）

需求是：不要把云盘固定塞在应用共享目录里，要能挂到自己想放的位置 ——
尤其要挂进飞牛「文件」里能直接看到的**个人空间**（`/volN/<uid>`，例如 `/vol4/1000`）。

| 变更 | 说明 |
|---|---|
| **管理台加「浏览…」目录选择器** | 挂载位置输入框旁边多一个按钮，弹出目录选择器（v1.2.1 起改版为「文件夹树 + 目录内容」两栏，见上一节）；顶部有快捷入口：各卷的「个人空间（用户名）· /vol4」与「当前挂载点」。列表里直接标出属主与状态（空目录 / 非空 / 已是挂载点），目录不存在时可一键「新建文件夹」 |
| **安全护栏** | ① 只接受绝对路径且必须落在存储卷（`/vol1…/volN`）内；② 不能挂卷根（会遮住整卷）；③ 不能落在应用自己的配置/暂存/日志目录上下；④ 目标在**当前挂载点里面**时不算错误 —— 会先卸下当前挂载点，再看/建真实目录、然后挂上（v1.2.1 起，为的是能从「个人空间根」挪进子目录）；⑤ 目标目录**非空**时先拒绝，要勾选「我确认会遮住目标目录里原有的内容」才允许（数据不会丢，只是被遮住） |
| **切换先卸旧的** | 换挂载点会先卸载原位置再改配置、再挂新位置；如果新位置挂不上，配置与挂载**自动回滚**回原处。原来的实现按「配置里的路径」卸载，切换时会漏掉旧挂载留下僵尸（被 `TestSetMountPointMovesMount` 抓到的真 bug） |
| **守护进程改为以 root 运行** | 任意位置（尤其别的用户的个人空间）都需要 root 才能建目录/挂载，CloudDrive2 等同机方案也是这么做的。挂载内容的归属仍由配置里的 uid/gid 决定（选个人空间时会自动跟随为「该用户:Users」，例如 `1000:1001`），所以文件在用户眼里就是自己的。想改回指定用户：在 `/vol4/@appconf/cmccyun/` 放一个 `run_as` 文件，内容写用户名（如 `cmccyun`） |
| **记住「实际挂在哪里」** | 配置目录里的 `mounted_at` 记录实际挂载点：进程被强杀、或外部改了挂载点后重启，守护进程会先把旧位置的僵尸挂载卸掉，再挂到新位置；`cmd/main stop` 也会两个位置都检查一遍 |

效果：把挂载位置设成 `/vol4/1000/移动云盘` 后，该用户在「文件」里直接就能看到云盘目录，
SMB 共享、影视刮削、Emby 之类的也能直接指过去（读权限、属主都正常）。

### v1.1.3 变更：又一处锁问题 + 过期预签名地址自愈

一次「再检查一遍」的审计中，用「测试先失败再通过」的办法挖出并修掉两个真问题：

| 变更 | 说明 |
|---|---|
| **挂载不再持锁做网络请求** | `Mount()` / `Remount()` 原来在**持服务锁**的状态下调用 `c.Init()`（要访问云端），云端慢或不通时整个管理台会**卡住不响应**（连日志页都打不开）。现在拆成三段：持锁准备客户端 → **放锁**做网络连接 → 再持锁挂载。单测 `TestConnectDoesNotHoldServiceLock` 兜住（我把持锁调用临时塞回去验证过它会失败） |
| **过期预签名地址自愈** | 上传分片 / 下载 CDN 链接都是**预签名 URL**，有过期时间。以前只有鉴权类错误才重新签名，现在 400/401/403/404/409/410 都视作「这条地址不能用了」，上传会自动重新签名剩余分片并重试、下载会重新拉一次 CDN 链接。单测 `TestUploadResignsOnExpiredPartURL`（404，不涉及鉴权）兜住 |

### v1.1.2 变更：修掉续期死锁 + 让恢复过程可验证

| 变更 | 说明 |
|---|---|
| **修复死锁** | 挂载过程中若触发令牌续期（安装后第一次挂载最容易碰上：旧授权已失效），守护进程会**卡死**——续期回调里要拿服务锁，而挂载路径正持着那把锁。现在回调在自己的 goroutine 里执行，不再与调用方抢锁。单测 `TestRefreshCallbackDoesNotDeadlockUnderServiceLock` 兜住（回归时它会超时失败） |
| 恢复过程写日志 | 每次「鉴权失败 → 续期 → 重试」都写进运行日志（管理台「日志」页可见）：`[鉴权恢复] /file/list 鉴权失败，立刻强制续期后重试` / `[鉴权恢复] 续期成功，/file/list 已用新令牌重试通过`；失败时写 `续期未成功（…）` 与放进「最近错误」 |
| 端点可覆写 | 新增 `CMCCYUN_ROUTE_BASE`、`CMCCYUN_REFRESH_URL` 环境变量（走代理镜像，或让测试把真守护进程指向假服务） |

### v1.1.1 变更：鉴权失败「即错即续期、自动重试一次」

以前只有「启动时 + 每 6 小时」两个检查点，如果令牌在检查点之间被服务端判失效，接下来的操作
会直接报错，直到下一次巡检。现在改成**事件驱动 + 巡检兜底**（对齐 OpenList 的做法）：

| 场景 | 行为 |
|---|---|
| 任意 JSON 接口被拒（HTTP 401/403、`code=10401/12002`、message 含「登录/授权/鉴权/凭证/token」等） | 立刻调 AAS 续期接口换新令牌，然后**用新令牌重放同一次请求**，成功则用户完全无感 |
| 分片上传中途地址被拒 | 重新签发剩余分片的预签名地址后继续上传，不再整次上传报废 |
| CDN 直链下载被拒（401/403/410） | 重新取一次直链再下 |
| 一堆并发请求同时撞上失效 | 只续期**一次**，其余请求等这次续期结果后直接用新令牌重试（`refreshMu` 串行 + 凭据比对） |
| 续期后仍被拒 / 续期接口本身挂了 | 30 秒（成功）/ 2 分钟（失败）内不再重复打扰续期接口，避免忙时把续期接口打爆；错误原样上报并显示在管理台「最近错误」 |
| 业务错误（同名文件已存在、文件不存在…） | 不触发续期，保持原样返回 |

判定依据：只把「鉴权类」错误当作失效信号；业务错误、5xx（由分片重试负责）都不续期。

### v1.1.0 变更：借鉴 CloudDrive2 与 OpenList

| 借鉴点 | 实现 | 效果 |
|---|---|---|
| CloudDrive2 的**覆盖写入** | `internal/vfs/overlay.go`：编辑云盘上已有文件时，暂存文件只保存**被改动的字节区间**，没碰到的部分在读取和上传时按需从云端拉取 | 改大文件里的几个字节，不再「整文件下载 → 改 → 整文件重传」。实测 30 MB 文件改 18 字节，本地暂存只占 **16 KB** |
| OpenList 139 驱动的**分片重试** | `internal/api/retry.go`：每个分片上传失败自动重试 3 次（500 ms→1 s→2 s 退避），只重试网络类错误（连接重置、超时、5xx/429），鉴权错误立即失败 | 弱网/偶发 5xx 不再整次上传报废 |
| OpenList 139 驱动的**令牌续期** | `internal/api/client.go`：`RefreshToken` 同时尝试「完整 ticket」与「纯 token」两种形状（不同部署接受的不同），解析新令牌有效期并回调持久化 | 见上，授权可自动续期；管理台顶部新增「授权 剩余 X 天」徽标、「刷新令牌」按钮（`POST /api/auth/refresh`）与暂存占用显示 |
| — | 修复：FUSE 对 `O_TRUNC` 新建文件会**先 flush 再 write**，早期版本会把暂存文件删掉导致写入丢失（v1.1.0 修复，并有单测 `TestCreateSurvivesFlushBeforeFirstWrite` 兜住） | 新建 + 写入不再丢数据 |

## 3. 安装

### 方式 A：应用中心图形界面（推荐）

1. 应用中心 → 左下角「设置」→ 打开**手动安装**开关（或执行 `sudo appcenter-cli manual-install enable`）。
2. 拖入 / 选择 `cmccyun.fpk`。
3. 选择**安装卷**（应用本体与数据会装到该卷，例如 `/vol4` 对应卷 4）。
4. 按向导填写（见下），完成后应用会自动启动。

### 方式 B：命令行

```bash
# --volume 必填：目标卷序号（/vol4 → 4）。省略会报默认卷为 0 的错误。
# --env 是可选的向导预填文件，格式为 wizard_* 键值对。
cat > /tmp/cmccyun-install.env <<'EOF'
wizard_mount_subdir=移动云盘
wizard_readonly=rw
wizard_authorization=
EOF

sudo appcenter-cli install-fpk ./cmccyun.fpk --volume 4 --env /tmp/cmccyun-install.env
sudo appcenter-cli start cmccyun      # 安装流程通常已自动启动
```

### 向导项

| 字段 | 含义 |
|---|---|
| `wizard_authorization` | 授权串（可留空，装完后在管理台里填） |
| `wizard_mount_subdir` | 挂载目录名，落在应用共享目录 `/volN/@appshare/cmccyun/` 下，默认 `移动云盘` |
| `wizard_readonly` | `rw` 读写 / `ro` 只读 |
| `wizard_mount_point`（仅「设置」里有） | 自定义绝对挂载路径，如 `/vol4/1000/移动云盘`（`1000` 是登录账号的 uid，挂到这里在「文件」里最直观） |

### 安装后落盘位置

| 路径 | 内容 |
|---|---|
| `/vol4/@appcenter/cmccyun/` | 程序本体（两个二进制 + `fnos-common.sh` + `ui/`），`/var/apps/cmccyun/target` 软链到这里 |
| `/vol4/@appconf/cmccyun/config.json` | 配置（含授权串，权限 `0600`，属主 `cmccyun`） |
| `/vol4/@appdata/cmccyun/` | `cmccyun.log`、`stdout.log`、`staging/`（上传暂存）、`cmccyun.pid` |
| `/vol4/@appconf/cmccyun/mounted_at` | 实际挂载点（切换位置 / 异常退出后自救用） |
| `/vol4/@appconf/cmccyun/run_as` | 可选：让守护进程改回以某个普通用户运行（默认 root） |
| `/vol4/@appshare/cmccyun/` | 共享文件夹，里面的子目录即云盘挂载点 |

安装时会自动：创建 `cmccyun` 系统用户、把 `/etc/fuse.conf` 补上 `user_allow_other`
（挂载内容对其它用户可见 —— 挂在别人的个人空间里时也要能被 SMB / 「文件」读到）。
守护进程从 v1.2.0 起默认以 **root** 运行，这样才能在任意位置建挂载点。

## 4. 获取 Authorization（关键一步）

1. 电脑浏览器打开 <https://yun.139.com> 并登录。
2. `F12` → **Network** 面板 → 过滤 `yun.139.com` → 随便点一个接口（如 `/orchestration/personalCloud/*`）。
3. 在 **Request Headers** 里找到 `Authorization`，复制它的值：形如
   `Basic cGM6MTM4MDAxMzgwMDA6ZXlK...`（一整串 base64）。
4. 打开管理台 `http://<NAS_IP>:19898/` → 粘贴 → 「保存并挂载」。

> 不要把开头的 `Authorization: ` 一起粘进去，只要冒号后面的值。
> 授权串等价于网页登录态，请勿外发；它在 NAS 上以 `0600` 保存在 `config.json`。

## 5. 使用

- fnOS 桌面会出现「移动云盘」图标（**仅管理员可见**），点开即管理台；也可以直接访问 `http://<NAS_IP>:19898/`。
- 管理台（v1.3.0 起按页签分区：**挂载设置 / 授权 / 云盘浏览 / 运行日志**）可做：
  **顶部状态卡**实时显示「**已挂载 / 未挂载**」+ 挂载路径（可一键复制）、账号、模式（只读/读写）、属主 `uid:gid`、
  令牌剩余天数、是否开机自动挂载、进程 PID（每 5 秒自动刷新，不用手动点）；
  挂载 / 卸载 / 重新挂载、填授权（含**令牌剩余天数徽标**与「刷新令牌」按钮）、**挂载位置（「浏览…」两栏目录树选择器，任选位置）**、
  只读开关、权限位（默认 `0666`/`0777`）、目录缓存秒数、上传分片大小（默认 100 MB）、宿主 uid/gid、实时日志。
  另显示「暂存占用 X MB / N 个文件」，用于确认覆盖写入没有把大文件落到本地磁盘。
  按钮有加载态与禁用态，请求带超时（不会无限转圈），成功/失败都有气泡提示。
- **挂载点想放哪就放哪**（v1.2.0 起）：默认在共享目录 `文件` → 共享文件夹 `cmccyun` → `移动云盘`；
  点「浏览…」弹出**文件管理器式两栏选择器**（v1.2.1 起）：左边文件夹树点 `▸` 展开、点名字选中，
  右边是所选目录的内容（点一行进去），也可以用「路径」框直接粘贴路径跳转。**推荐挂进自己的个人空间**，
  例如 `/vol4/1000/移动云盘`（`1000` 是账号 uid，可在「设置 → 用户」或用 `id <用户名>` 看到）——
  这样在「文件」首页就能直接看到云盘，SMB / 影视刮削也都能直接指过去。
  注意**别挂到个人空间的根**（`/vol4/1000` 本身）：那会把你原有的文件夹遮住；真挂错了也不要紧，
  在同一选择器里选 `/vol4/1000/移动云盘` 再点「挂到这里」即可 —— 它会先卸下原位置、把目录建出来、再挂上。

### 客户端标识与上传上限

守护进程默认带 `X-Yun-Client-Info: ...:13`（PC 客户端标识），据此云端放宽单文件上限
（网页/App 50 GB、PC 客户端 500 GB 量级；官方开放平台普通用户仅 4 GB）。
超大文件会自动分片上传，分片大小由 `upload_part_mb` 控制。

## 6. 常见运维

```bash
# 状态 / 启停（fnOS 托管）
sudo appcenter-cli status cmccyun
sudo appcenter-cli start  cmccyun
sudo appcenter-cli stop   cmccyun

# 应用自己的状态与挂载点

# 日志
tail -f /vol4/@appdata/cmccyun/cmccyun.log     # 守护进程日志（管理台同源）
tail -f /vol4/@appdata/cmccyun/stdout.log      # 生命周期脚本输出
tail -f /var/log/apps/cmccyun.log              # 安装/升级脚本的诊断输出
```

**卸载**：在应用中心界面点卸载即可（先自动停服务、卸挂载）。
`appcenter-cli uninstall` 在飞牛上会被拒绝（提示「请在 Web UI 卸载」），
命令行环境下可执行 `tests/fnos-reinstall.sh` 里的手工流程：

```bash
sudo appcenter-cli stop cmccyun
sudo env TRIM_APPDEST=/vol4/@appcenter/cmccyun TRIM_PKGETC=/vol4/@appconf/cmccyun \
        TRIM_PKGVAR=/vol4/@appdata/cmccyun bash /var/apps/cmccyun/cmd/uninstall_init
sudo env TRIM_APPDEST=/vol4/@appcenter/cmccyun TRIM_PKGETC=/vol4/@appconf/cmccyun \
        TRIM_PKGVAR=/vol4/@appdata/cmccyun wizard_keep_data=delete \
        bash /var/apps/cmccyun/cmd/uninstall_callback
```

**残留挂载**（异常退出时）：

```bash
mount | grep cmccyun
sudo fusermount3 -uz /vol4/@appshare/cmccyun/移动云盘   # 懒卸载，必成功
```

v1.3.0 起这种「躺在地上」的残留（`kill -9` / 掉电后留下的空壳，访问即报
`Transport endpoint is not connected` / `ENOTCONN`）会**自动处理**：启动时与点挂载时都会先卸掉再重挂；
配置里的位置与残留位置不一致时，管理台会给出提示并提供**一键清理**按钮。上面这条命令只是兜底。

```bash
bash make-fixtures.sh    # 造 /tmp/cct/backend（文本 + 3 MB + 25 MB 假文件）
bash fake-daemon.sh start   # 隔离实例：cmccyun-test + 端口 19896（不碰线上真挂载）
bash functional.sh       # 跑 23 项功能测试
bash fake-daemon.sh stop
```

> `restart.sh` 从 `/tmp/cmccyun-build/cmccyun` 起一个假后端实例，默认端口 19898 会撞上线上管理台 ——
> 本机跑时用 `CMCCYUN_PORT=19895 CMCCYUN_MOUNT=/tmp/cct/mnt bash tests/restart.sh`（端口填任一空闲值即可，
> 别撞上 19898 线上管理台；不传 `CMCCYUN_MOUNT` 会报「尚未设置挂载目录」而只起界面）。`/tmp` 被系统清过后
> 要先 `bash tests/make-fixtures.sh`，并把二进制重新编到 `/tmp/cmccyun-build/cmccyun`。
>
> `functional.sh` **不会自己搭环境**：它只对着已经挂好的 `/tmp/cct/mnt` 跑，所以顺序是
> `make-fixtures.sh` → 编译 `/tmp/cmccyun-build/cmccyun` → `restart.sh` → `functional.sh`
> （少了中间两步会看到 18 项 FAIL、全是 `No such file or directory`，不是真 bug）。

> 注意端口与进程名：`restart.sh` 开头的 `pkill -x cmccyun` 会连带杀掉真机上正在跑的真实例
> （真机上的守护进程 `comm` 其实是 `cmccyun-linux-a`，所以 `pkill -x cmccyun` 打不中它——别指望用
> 这个命令停服务，**停服务请用 `appcenter-cli stop cmccyun`**）。
> 调试隔离实例用 `fake-daemon.sh`（二进制名 `cmccyun-test`、端口 19896、自己的配置）；
> 避开 19897（鉴权恢复演示）、19898（线上管理台）、19899（生命周期/FUSE 测试）这几个端口。
>
> 想保留已填的授权做重装/覆盖升级：**不要**用 `fnos-reinstall.sh`（它会 `rm -rf /vol4/@appconf/cmccyun`，
> 授权一起没了）。已安装状态下直接用 `appcenter-cli install-fpk …` 全新装（`check` 为 Not Installed 时）
> 或按 Web UI 等效步骤覆盖（`fnos-upgrade-sim.sh`）；安装向导只在字段为空时回填，`config.json` 里已填的
> 授权不会被清掉。

## 8. 排错

| 现象 | 处理 |
|---|---|
| 页面上**有东西一直在转 / 一直在动**，说不清是哪个元素 | 打开控制台按 F12，粘到 Console 里跑：`[...document.querySelectorAll('*')].filter(e=>getComputedStyle(e).animationIterationCount==='infinite'&&getComputedStyle(e).animationName!=='none').forEach(e=>console.log(getComputedStyle(e).animationName,e.className,e.getBoundingClientRect()))` —— 会列出所有无限动画元素，转圈的是 `rot`，呼吸灯是 `pulse`（正常）。v1.3.1 顶栏那个「一直在转的线」就是这么抓到的 |
| 点挂载后**一直显示「正在挂载」**、状态接口也超时 | v1.2.1 及更早版本的真 bug（配置保存路径自我死锁，把所有接口一起锁住），**v1.3.0 已修**。旧版本上只能 `appcenter-cli stop/start cmccyun` 恢复；升级到 v1.3.0 后按钮带超时与报错，不会再无声转圈。怀疑卡住时用 `sudo kill -QUIT <pid>` 把 goroutine 栈打到 `/vol4/@appdata/cmccyun/stdout.log` 定位 |
| 挂载点访问报 `Transport endpoint is not connected` | 僵尸挂载（进程被强杀/掉电遗留）。v1.3.0 起启动与点挂载时自动清理；也可手工 `sudo fusermount3 -uz <路径>` |
| 挂载点里没有文件、日志报 401/鉴权失败 | 授权过期，按第 4 节重新抓 `Authorization` 填进管理台 |
| 桌面图标点开空白 | 确认应用在运行（`appcenter-cli status cmccyun`）、端口 19898 可访问；`checkport=true` 时端口被占用会导致启动失败 |
| 顶栏「**授权 剩余 N 天**」是什么意思 / 会不会到期就断 | 它 = 你贴的那条 `Authorization` 自身的剩余有效期（约 30 天），**不是会员到期日**；不足 15 天时应用每 6 小时自动续期，成功后回到约 30 天，所以正常不用管（v1.3.2 起鼠标悬停徽标/状态卡/授权页即可看到这段说明）。真要确认续期可用，点「刷新令牌」手动续一次，再看「上次自动续期」 |
| 启动失败 | 看 `/vol4/@appdata/cmccyun/stdout.log` 与 `/var/log/apps/cmccyun.log`（失败时最后 15 行日志会自动附加到应用中心的报错提示里） |
| 普通用户看不到挂载内容 | 确认 `/etc/fuse.conf` 含 `user_allow_other`（安装脚本会自动写入），并重启应用 |
| 上传大文件失败 | 降低「上传分片大小」（`upload_part_mb`，默认 100 MB）或留意会员单文件上限 |
| 卸载后目录还在 | 云盘文件不会被删；共享目录里的空目录可手工删除，应用数据按卸载向导选择保留/删除 |
| 「文件」里看不到挂载的云盘 | 挂载点要选在用户可见的空间里（个人空间 `/volN/<uid>`，如 `/vol4/1000/移动云盘`）；挂到 `/volN/@appshare/...` 这类共享目录在「文件」里通常不好找。切换后如仍看不到，刷新「文件」页面 |
| 切换挂载位置报「目录非空」 | 目标目录里已有内容，挂上去会把这些文件遮住（数据不丢）。确认要挂就勾选「我确认会遮住目标目录里原有的内容」 |
| 「文件」里自己原有的文件夹不见了 | 挂载点选成了**个人空间的根**（如 `/vol4/1000` 本身），原有文件夹被云盘遮住了。用「浏览…」选 `/vol4/1000/移动云盘` 再点「挂到这里」，会自动卸下原位置再挂，原有文件夹随即恢复 |
| 提示「某某在当前挂载点里面」 | 说明选的位置被当前挂载遮着（看到的其实是云盘内容）。点「挂到这里」即可：它会先卸下当前挂载点，再核对/创建真实目录并挂上。反过来「在选中目录里新建文件夹」在这种位置会被拒（那会直接建到云盘里） |
| 切换位置后旧位置还有残留挂载 | 正常情况下会自动卸载；若上一次进程被强杀，重启应用即可（守护进程会按 `mounted_at` 把旧位置的僵尸挂载清掉），或手工 `sudo fusermount3 -uz <旧路径>` |
| 想改回普通用户运行 | 在 `/vol4/@appconf/cmccyun/` 放 `run_as` 文件（内容为用户名，如 `cmccyun`）后重启应用；此时只能在应用用户有权限的位置建挂载点 |

## 9. 已知取舍

- **管理台无鉴权**，监听 `0.0.0.0:19898`。仅建议在可信内网使用；要收紧可在
  `config.json` 里把 `web_listen` 改为 `127.0.0.1`（此后只能从 NAS 本机访问）。
- **守护进程以 root 运行**（v1.2.0 起，为了能挂到任意位置，与 CloudDrive2 等同机方案一致）：
  云盘的所有读写请求都由它发出，挂载内容的可见性由配置里的 uid/gid 与权限位决定。
  介意这一点可以在 `/vol4/@appconf/cmccyun/run_as` 里指定普通用户（代价：只能挂在该用户有权限的位置）。
- **挂载点非空需要二次确认**：确认后原内容只是被「遮住」（`mount` 覆盖），卸载即恢复，不会删除。
  同理，**别把挂载点设成个人空间的根**（`/vol4/1000`）；选择器会警告并建议改成其下的子目录（如 `/vol4/1000/移动云盘`），选错后用「挂到这里」挪出来即可。
- **位置选择器只列出真正挂载了文件系统的存储卷**：`/vol00`、`/vol01`、`/vol02` 这类飞牛预建的占位目录（系统盘上的普通目录）不会出现在树里，也不允许挂（既不在「文件」里显示，又会占系统盘）。
- 非官方接口：不保证长期可用；如失效，改动集中在 `internal/api/`。
- **写放大**：覆盖写入模式下，上传时仍需按顺序把「云端旧区间」读一遍并随新对象推送
  （服务端要求顺序分片）。省掉的是本地磁盘占用与整文件下载，而不是上传流量；
  只改几字节的极小改动，上传量仍约等于文件大小——这是接口限制，CD2 同样如此。
- 调试后门：`CMCCYUN_DEBUG_FAKE=<本地目录>` 会让守护进程挂本地目录而非云盘（测试用），
  正式环境不要设置该环境变量。
- 授权串与云盘账号等权（网页版能做的都能做），请妥善保管。
